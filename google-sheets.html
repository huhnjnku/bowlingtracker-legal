Google Sheets Integration

The Google Sheets bridge lets you push live match scores to a Google Sheet in real time. Useful for:

  • Public broadcast scoreboards
  • Athletic department displays
  • Historical archives your program already maintains in Sheets
  • Any downstream consumer that reads a Google Sheet (Slack integrations, dashboards, etc.)

Prerequisites

You need:

  • Live Match Scoring enabled (this is a premium-only feature)
  • A Google account
  • A Google Apps Script Web App that accepts POSTs and writes to your spreadsheet
Why a webhook and not the Sheets API directly? A webhook is dramatically simpler to set up and doesn't require handing OAuth credentials to a third-party app. You control the script; the script controls what gets written to which cells.

Step 1 — Create Your Spreadsheet

Open Google Sheets and create a new spreadsheet. The layout the app expects (a suggested template):

  • Rows 1-11 for lineup rows: 8 starters + 3 subs
  • Columns A-G for game data (name in A, games 1-6 in B-G)
  • Column I for row totals
  • Three additional rows below the lineup for baker games

The exact cell layout is up to your Apps Script — the app sends a structured JSON payload and you decide where to place each field.

Step 2 — Create the Apps Script

  1. In your spreadsheet: Extensions → Apps Script.
  2. Delete the default myFunction.
  3. Paste a script that reads the POST body and writes into the sheet. Minimal starter:
function doPost(e) {
  const payload = JSON.parse(e.postData.contents);
  const sheet = SpreadsheetApp.getActiveSheet();

  // payload.homeSchool, payload.opponentName, etc.
  // payload.matchDate — ISO string
  // payload.lineup — array of 11 slot objects with { playerName, games: [g1..g6], total }
  // payload.baker — { games: [g1..g6], total }
  // payload.opponentTotals — array for tri/quad
  // payload.matchIsFinalized — boolean

  sheet.getRange('B1').setValue(payload.homeSchool);
  sheet.getRange('B2').setValue(payload.opponentName || '');

  payload.lineup.forEach((slot, i) => {
    const row = i + 4; // starts at row 4
    sheet.getRange(row, 1).setValue(slot.playerName || '');
    slot.games.forEach((g, j) => {
      sheet.getRange(row, 2 + j).setValue(g || '');
    });
    sheet.getRange(row, 9).setValue(slot.total || ''); // col I
  });

  return ContentService.createTextOutput('OK');
}

Customize the cell mapping to match your spreadsheet.

Step 3 — Deploy as Web App

  1. In Apps Script: Deploy → New deployment.
  2. Type: Web app.
  3. Execute as: Me.
  4. Who has access: Anyone. (The webhook URL is your secret — treat it like a password.)
  5. Click Deploy.
  6. Copy the Web app URL that ends in /exec.

Step 4 — Wire the Webhook into the App

  1. In Bowling Tracker → Settings → find your squad in the LMS section.
  2. Tap the Sheets icon in the squad row.
  3. Paste your Web App URL into the Webhook URL field.
  4. Tap Save.

The squad row now shows a green Sheets pill.

What Gets Sent, and When

While you're scoring an eligible match (H2H or Tournament, not Open Tracking):

  • The publisher sends a snapshot to your webhook on every score change, then coalesces via a debounce.
  • Each snapshot is a fixed 11-slot lineup (bowlers 1-8 + subs 1-3) plus a baker block.
  • Empty slots are still sent, just with blank scores — this keeps the row structure predictable.
  • Column I totals are included in the payload as pre-computed values.
  • On network errors, the app retries once silently before giving up on that snapshot.

Status Indicators

In Settings, next to the squad name:

  • Green Sheets pill — webhook is configured.
  • Under the pill: Last sent at HH:MM:SS — updates on every successful POST.
  • Orange text — appears if the most recent POST failed. Common causes: expired script deployment, permission changes, script errors.

Clearing the Webhook

Open the Sheets config sheet → tap Clear. The webhook URL is removed and pushing stops. The rest of Live Match Scoring keeps working.

Common Gotchas

Redeployments change the URL. If you edit your Apps Script and hit Deploy → New Deployment, you get a new URL. Update the webhook in Bowling Tracker to match. Alternatively, use Manage Deployments to edit the existing one — that keeps the URL stable.
Apps Script has quotas. Google limits free Web Apps to something like 20,000 URL fetches per day and 6-minute execution time per call. For normal live scoring you'll never hit them, but if your script does heavy processing it might time out.
You can share the sheet without exposing the webhook URL. Publish the spreadsheet as a webpage or share it view-only — parents and staff see the live scores, and only you know the webhook URL.
